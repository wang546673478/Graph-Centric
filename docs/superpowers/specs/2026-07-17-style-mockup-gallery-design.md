# Style Mockup Gallery — Design

**Date:** 2026-07-17
**Status:** Approved (pending user spec review)
**Owner:** user + assistant

## Goal

User thinks the current webui visual style is ugly. They want to see **multiple competing
visual directions rendered as image mockups** before committing to a redesign. After they
pick, the chosen style (plus any other styles they want to keep) becomes a **runtime
switchable theme** in the actual webui — not just one style locked in.

This spec covers **Phase 1 only** (mockup gallery). Phase 2 (theme switcher implementation
in webui) gets its own spec after the user picks a winning direction.

## Phase 1 Deliverables (this spec)

1. **8 PNG mockups** at 1440×900, generated via `mmx image generate`, in `mockups/`:
   - `01_minimal-light.png`
   - `02_minimal-dark.png`
   - `03_glassmorphism-light.png`
   - `04_glassmorphism-dark.png`
   - `05_notion-light.png`
   - `06_notion-dark.png`
   - `07_bento-light.png`
   - `08_bento-dark.png`
2. **`mockups/index.html`** — single static HTML page, no dependencies, CSS-grid layout,
   one card per mockup with title + light/dark chip + one-line caption.
3. **`serve-mockups.sh`** — one-shot shell script that starts `python3 -m http.server
   8090 --bind 0.0.0.0` from inside `mockups/` and prints the LAN URL.
4. **Background HTTP server** running so the user can browse from any LAN device.

## Mockup Content (must be identical across all 8)

To make styles compare apples-to-apples, every mockup shows the **same scene**:

- **Left sidebar (~220 px):** "Graph-Centric Agent" header, search input, 4 run list items
  - "Refactor auth flow" — Running (purple, animated dot)
  - "Add CSS grid layout" — Done (green)
  - "Build skill compiler" — Paused (amber)
  - "Investigate skill match" — Error (red)
- **Top bar:** graph title "refactor/auth", model chip "MiniMax-M2.7", token counter, action buttons
- **Center:** cytoscape-rendered graph — 6-8 nodes with mixed status (1 running, 2 done,
  1 error), edges between them, one node highlighted/selected
- **Right panel:** placeholder card reading "对话 / 顾问面板 · Phase 3" with hint text

Status colors shown: accent (#7c3aed) for Running, green for Done, amber for Paused, red for Error.

## Hosting & LAN Access

- **Server:** `python3 -m http.server 8090 --bind 0.0.0.0` running in background.
- **Document root:** `mockups/` (so `index.html` is at `/`, images at `/01_…png`).
- **Bound interface:** `0.0.0.0` so any device on the LAN can reach it.
- **URL handed to user:** `http://<host-LAN-IP>:8090/`. IP discovered via
  `hostname -I | awk '{print $1}'` (Linux) at server-start time.
- **Port-conflict fallback:** if 8090 is busy, retry 8091..8099, error out at 8100.
- **Stop:** assistant can kill via `lsof -ti:8090 | xargs -r kill` or equivalent.

## Error Handling

| Failure | Behavior |
|---|---|
| `mmx` auth not configured | Prints clear "run `mmx auth login`" message, no images, abort. |
| Single image generation fails / times out | Card shows "Failed — regeneration needed" placeholder PNG (gray box + label). Generation continues for others. |
| All 4 styles of a mode fail | User told via chat; can fall back to asking user to retry or skip. |
| Port 8090-8099 all in use | Server does not start; user told to free a port or wait. |
| LAN IP not discoverable | Fall back to `localhost:8090` and tell user that LAN may need firewall rule. |

## Testing

The assistant verifies (before handing URL to user):
1. `curl -fsS http://localhost:8090/` returns 200 with HTML body referencing all 8 images.
2. `curl -fsSI http://localhost:8090/<image>.png` returns 200 + `Content-Type: image/png`.
3. LAN IP is non-loopback (e.g. starts with `192.` or `10.`).
4. The user confirms visual rendering on at least one LAN device.

## Out of Scope (Phase 2 will cover)

- Implementing the chosen style(s) as actual CSS in webui.
- A "style switcher" UI component (dropdown, keyboard shortcut, persisted to localStorage).
- Removal or replacement of the existing `data-theme="light"|"dark"` toggle.
- Any changes to `webui/src/components/**` or `webui/src/styles/main.css`.

## Exit Criteria

User says something like "用 Minimal dark" (or picks 1-4 styles). The assistant confirms,
stops the HTTP server, captures the picked images into a follow-up spec / plan, and proceeds
to Phase 2.

If user wants to regenerate some mockups with new prompts, repeat only those; existing files
are overwritten.

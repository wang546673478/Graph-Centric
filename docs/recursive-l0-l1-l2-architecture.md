                            Scope 收敛法则

   SubAgent 在 login() 内部工作时:
   ├── 它的"世界" = login() 的子图 (validate_email, hash_pw, check_db)
   ├── 它的 ScopeGuard = login() 子图中所有节点的文件行范围
   │   (auth.rs:47-85, 总共 37 行)
   ├── 它的 L0 上下文 = login() 子图的 3 个节点 + 2 条边
   ├── 它的 L1 上下文 = 3 个节点的 responsibility/inputs/outputs
   ├── 它的 L2 上下文 = 37 行代码
   └── LLM 输入总量 ~ 37 行代码 × 1层 = 37 行 (不是 10000 行)

   级联回溯:
   ├── check_db() 失败 → 沿 Calls 边回溯验证 hash_pw() 和 validate_email()
   ├── login() 子图内修复 → 不需要上升到 auth.rs 层级
   ├── 只有锚点级矛盾 (login() 的 L1 spec 本身不可行) → 上升到父层 auth.rs

                           区别: 不是"深度学习"的多层

   ❌ 不是神经网络那种每层抽特征
   ✅ 递归是因为复杂节点的内部也需要正确性保障

   不需要预定义多少层:
   ├── 简单的函数 → 不展开
   ├── 复杂的函数 → 展开一层  
   └── 更复杂的函数 → 递归展开
   引擎自己判断要不要下钻
